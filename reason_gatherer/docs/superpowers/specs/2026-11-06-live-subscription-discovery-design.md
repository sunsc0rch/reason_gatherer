# Дизайн: обнаружение рабочих URL подписок Throne

## Цель

Помимо отдельных VPN-конфигов находить в текущих источниках URL сторонних самообновляемых подписок и публиковать прошедшие проверку URL в отдельном файле для импорта в Throne.

## Критерий рабочей подписки

URL должен успешно отдавать содержимое, из которого парсер извлекает поддерживаемые VPN-конфиги. Подписка считается рабочей, если хотя бы один содержащийся в ней узел проходит полный tunnel-тест, включая проверку TLS-сертификата. Ссылка сохраняется в отдельный список `results/subscriptions.txt`.

## Область изменений и ограничения

- Искать ссылки в содержимом всех текущих типов источников: файлах GitHub-репозиториев, ответах прямых URL и постах Telegram.
- Проверять найденные URL как подписки: получать содержимое, декодировать/разбирать поддерживаемые форматы и проверять узлы существующим tunnel-тестером.
- Не помещать в `subscriptions.txt` обычные ссылки, недоступные URL, непарсящиеся ответы и подписки без хотя бы одного прошедшего узла.
- Повторяющиеся URL сохранять один раз; при очередном запуске обновлять список по актуальным результатам проверки, чтобы умершие подписки исчезали.
- Запускать весь поиск и проверку только отдельным CLI-флагом `--subscriptions`. Не встраивать эту работу в `--collect`, `--test`, `--full` или `--recheck`.
- Файл содержит URL подписок, а не их развёрнутые конфиги. Статические списки конфигов и текущий `known_good.txt` остаются отдельными результатами.
- Проверка сертификатов должна соответствовать поведению Throne: для TLS нельзя отключать проверку сертификата. Это может исключить узлы, которые старый тестер ошибочно считал рабочими.

## Подходы

1. Извлекать URL из всего содержимого существующих GitHub, URL и Telegram-источников, затем скачивать и проверять возможные подписки. Выбранный подход: он охватывает уже настроенные источники без ручной разметки, хотя требует фильтровать обычные ссылки.
2. Обрабатывать только источники, вручную помеченные как подписки. Это уменьшает число ложных кандидатов, но пропускает ссылки внутри обычных файлов и сообщений и требует ручного сопровождения.

## Реализационные решения

- Использовать текущую конфигурацию источников и пайплайн парсинга/проверки, добавив извлечение HTTP(S)-ссылок из исходного текста.
- Добавить отдельную CLI-команду `--subscriptions`, которая целиком выполняет обнаружение и проверку подписок, не запуская и не меняя обычные этапы сбора конфигов.
- Не считать доступность HTTP-ответа достаточной: перед сохранением URL прогонять извлечённые узлы через полный tunnel-тест; достаточно одного прошедшего узла.
- Пересобирать `results/subscriptions.txt` только при запуске `--subscriptions`, публиковать его вместе с результатами и добавить ссылку/пример отдельного запуска в README.
- Не менять формат/назначение статических конфиг-листов.

## Открытые для реализации детали

Разработчик выбирает безопасное ограничение числа URL/узлов на одну подписку и использует имеющиеся таймауты и формат HTTP-загрузки проекта. Если конкретный источник недоступен, пропускает его без прерывания общего сбора.
